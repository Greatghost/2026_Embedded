# 底盘功率控制：无裁判系统/无电容板场景的问题分析与修复计划

## 一、摘要

当前车上**没有裁判系统、没有超级电容控制板**，电池直连底盘板与底盘电机。经代码追踪，现行功率控制策略层（`PowerControlTask` + `NingCap`）在这种硬件配置下会把底盘功率上限**错误地钳到 25W**，导致机器人几乎无法运动。本计划通过**运行时自动检测**（复用现有 `Offline_Task` 离线检测框架）实现优雅降级：裁判离线→电池直连默认功率（宏可调，默认 100W）；电容板离线→绕过电容状态机直通功率；硬件接回后自动恢复原逻辑，无需重编译。

## 二、现状分析（问题定位）

### 2.1 功率控制链路（现行架构，保留不动）

```
PowerControlTask (1kHz 策略层)
  → NingCapControl() 计算 cap_controller.set_power（底盘功率上限）
  → ChasisControlTask: set_robot_speed() 取 set_power → wheels_power_limit()
  → PowerLimit()（执行层，按电机模型二次方程削电流）——本层无问题，保留
```

### 2.2 无裁判 + 无电容板时的实际数据流（问题）

### 2.3 已有的可复用基础设施（探索确认）

1. **电容板离线检测已存在**：[Offline_Task.c:56-64](d:/HUST/Study/Robot/LangYa/Electic_control/2026_Embedded-Sentry/Sentry_Steer/Chassis/Task/src/Offline_Task.c#L56-L64) 通过 1Hz 对比 `super_power_debugger.recv_msgs_num` 计数，已维护 `offline_detector.super_cap_state = SUPER_CAP_ON/OFF`——但 PowerControlTask 从未使用它

## 三、修复方案

### 决策（用户跳过提问，采用推荐默认）

- 无裁判时默认功率 = **100W**（与代码内注释"先用100w"一致），做成显式宏便于调整
- 触发方式 = **运行时自动检测**（硬件接回自动恢复）

### 文件 1：[Offline_Task.h](d:/HUST/Study/Robot/LangYa/Electic_control/2026_Embedded-Sentry/Sentry_Steer/Chassis/Task/inc/Offline_Task.h)

- `enum ROBOT_SENSORS_DETECT` 末尾追加 `REFEREE_POWER_ON, REFEREE_POWER_OFF`（注释：掉线切默认功率）
- `OfflineDetector` 结构体追加两个字段（放在 `cap_receive_num` 与 `super_cap_state` 旁边，保持分组）：
  - `int16_t referee_0201_receive_num;`
  - `enum ROBOT_SENSORS_DETECT referee_power_state;`

### 文件 2：[Offline_Task.c](d:/HUST/Study/Robot/LangYa/Electic_control/2026_Embedded-Sentry/Sentry_Steer/Chassis/Task/src/Offline_Task.c)

在"超电板"检测块后追加裁判功率数据检测（同一 1Hz 周期、同一计数比较模式）：

```c

if (global_debugger.referee_debugger.cmd_0x0201_num != offline_detector.referee_0201_receive_num)

    offline_detector.referee_power_state = REFEREE_POWER_ON;
```

### 文件 3（主修改）：[PowerControlTask.c](d:/HUST/Study/Robot/LangYa/Electic_control/2026_Embedded-Sentry/Sentry_Steer/Chassis/Task/src/PowerControlTask.c)

**3a.** 文件顶部加宏与调试结构（遵循"每模块全局调试结构"约定）：

```c
/* 无裁判系统(离线/未安装)时的电池直连默认功率上限 W。
 * 有裁判时以 0x0201 chassis_power_limit 为准。 */
#define NO_REFEREE_POWER_LIMIT 100.0f

/* 功率策略调试记录 */
typedef struct {
    uint8_t referee_online;  // 1=裁判功率数据在线
    uint8_t cap_online;      // 1=电容板在线
    float  referee_power;    // 本周期采用的功率基准
    float  set_power;        // 本周期输出的底盘功率上限
} PowerCtrlDebug;
PowerCtrlDebug power_ctrl_debug; // 全局，调试器可观察
```

**3b.** 主循环重构功率基准选择（替换第 38 行）：

```c
if (offline_detector.referee_power_state == REFEREE_POWER_ON)
    referee_power = LIMIT_MAX_MIN(referee_data.Game_Robot_State.chassis_power_limit, 200, 30);
else
    referee_power = NO_REFEREE_POWER_LIMIT; // 无裁判:电池直连默认功率
```

**3c.** 策略分支改为电容板在线才走 NingCap 路径（替换 54-69 行的 if-else 链）：

```c
if (offline_detector.super_cap_state == SUPER_CAP_ON)
{
    // 电容板在线:原逻辑(飞坡/主动电容/过孔/普通)
    dynamic_cap_power = CapPowerSet();
    if (remote_controller.fly_state == IS_FLY)
        NingCapControl(buffer_energy, dynamic_referee_power, 300.0f);
    else if (remote_controller.super_power_state == POWER_TO_SuperPower)
        NingCapControl(buffer_energy, dynamic_referee_power, dynamic_referee_power + dynamic_cap_power);
    else if (gimbal_receiver_pack1.through_hole_flag)
        NingCapControl(buffer_energy, dynamic_referee_power, 45.0f);
    else
        NingCapControl(buffer_energy, dynamic_referee_power, dynamic_referee_power + dynamic_cap_power);
}
else
{
    // 电容板离线/未安装:电池直连,绕过电容电压状态机(不再 -5W 裁剪、不再算充电功率)
    cap_controller.set_power = gimbal_receiver_pack1.through_hole_flag ? 45.0f : dynamic_referee_power;
    cap_controller.cap_power = 0.0f;
}
```

**3d.** 250Hz CAN 发送块（74-79 行 `if (i % 4 == 0)`）整体加在电容在线分支内（离线时不再向 0x050 发帧）。

**3e.** 每周期末写入 `power_ctrl_debug` 四个字段。

**3f.** 在 [PowerControlTask.h](d:/HUST/Study/Robot/LangYa/Electic_control/2026_Embedded-Sentry/Sentry_Steer/Chassis/Task/inc/PowerControlTask.h) 补 `#include "Offline_Task.h"`。

### 不改动的内容（明确边界）

- `PowerLimit.c/.h` 执行层、`NingCap.c` 内部状态机、`set_robot_speed()` 速度映射——电容在线路径行为完全不变
- `SuperPower.c` 老驱动（已休眠）、INA260（未接线，不在本次范围）
- `PowerLimit.c:203` 舵电机 1.4 倍分配头寸：电池直连 100W 时理论瞬时上限 160W ≈ 7.3A@22V，远低于常规 6S 电池放电能力，无风险
- 死变量 `If_Game_Start`、注释代码保持原样（最小 diff）
