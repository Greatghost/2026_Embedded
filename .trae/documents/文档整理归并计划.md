# 文档整理归并计划

## 一、概述

在**不动任何 C 语言嵌入式代码**（.c/.h/Keil 工程文件）的前提下，将散落在仓库根目录、Sentry_Steer 根目录、Gimbal/Chassis 工程目录下的文档集中到 `Sentry_Steer/docs/` 分类归并；按用户确认的策略**激进删除**重复/旧版本/被整合取代的文档；清理构建日志与临时垃圾；调试 CSV 数据归档。所有移动用 `git mv` 保留历史，完成后创建一次提交。

**约束确认：**
- 只动 `.md/.pdf/.csv/.py/.png/.exe/.obj/.log/.bat` 等非工程文件；不碰任何 C 代码、Keil 工程文件（.uvprojx/.uvoptx 等）
- Gimbal 下三个"代码+数据"混合文件夹（`开机启动音效(诺基亚seeyouagain)/`、`Gravity_Compensation/`、`Pitch_Limit_Oscillation/`）整体原样保留
- `custom_client_path_viewer/`（Python 工具项目）、`killkeil.bat`、各工程 `README.md`/`LICENSE.md` 原样保留

## 五、假设与决策

1. 中文文件名在 PowerShell + git 下直接用引号路径操作；git mv 对未跟踪文件会失败，故先逐一确认跟踪状态（探索中已发现中文文件名在管道过滤中可能被编码吞掉，需用 `git ls-files --error-unmatch <path>` 逐个判断）
2. `analyze_pid.py`/`analyze_pid2.py` 是分析脚本非文档，留在 `Sentry_Steer/` 原地
3. `Gravity_Compensation/` 与 `Pitch_Limit_Oscillation/` 内含拟合脚本与数据关联紧密，整体保留在 Gimbal，不拆散
4. 根目录 `Ozone_DataGraph_260729.csv` 与 `Sentry_Steer/Ozone_DataGraph_260729.csv` 大小不同（438KB vs 178KB），是不同数据，都保留
5. 删除均走 git rm，git 历史可完整找回
6. `哨兵秘诀.md` 内容实为"哨兵调试记录"（调电机入门），归 debug/；`底盘裁判系统详解.md` 是 referee.h 结构体字段汇总，独特未被取代，归 protocol/
