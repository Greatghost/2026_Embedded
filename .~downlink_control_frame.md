# 上位机下发协议总览（给下位机）

Updated: 2026-07-11

## 1. 范围

本文描述 `gimbal_driver -> 下位机` 的紧凑串口下发 frame。下位机收到后，依 `DownlinkTypeID` 执行底盘/云台控制或封装对应的 RM2026 V2.0 裁判帧。

上行 `TypeID` 与下行 `DownlinkTypeID` 是两个独立编号空间。所有下行 frame 的 byte 0 都是 `0x21` (`'!'`)，byte 1 是 `DownlinkTypeID`；之后的 frame 长度由 ID 决定。

## 2. Frame 总表

| DownlinkTypeID | 名称                    | 总长度 | 裁判对接                      | ROS 来源                                                     |
| -------------- | ----------------------- | ------ | ----------------------------- | ------------------------------------------------------------ |
| `0x00`         | `GimbalControlFrame`    | 13B    | 无                            | `/ly/control/angles`、`/ly/control/vel`、`/ly/control/firecode` |
| `0x01`         | `SentryCommandFrame`    | 6B     | `0x0301 + data_cmd_id=0x0120` | `/ly/control/posture`、`/ly/control/sentry_cmd`              |
| `0x02`         | `MapPathFrame`          | 107B   | `0x0307 map_data_t`           | `/ly/control/map_path`                                       |
| `0x03`         | `CustomInfoFrame`       | 36B    | `0x0308 custom_info_t`        | `/ly/control/custom_info`                                    |
| `0x04`         | `SentryCoordinateFrame` | 17B    | 下位机自身坐标使用            | `/ly/bt/sentry_position`                                     |

下位机必须先读 byte 1，再按上表读取剩余字节；不可再把所有下发数据固定按 17B 解析。

## 3. `GimbalControlFrame`（`0x00`，13B）

| byte offset | 字段                 | 类型      | 说明                        |
| ----------- | -------------------- | --------- | --------------------------- |
| 0           | `HeadFlag`           | `uint8`   | 固定 `0x21`                 |
| 1           | `DownlinkTypeID`     | `uint8`   | 固定 `0x00`                 |
| 2           | `Velocity.X`         | `int8`    | 底盘 x 速度原始值           |
| 3           | `Velocity.Y`         | `int8`    | 底盘 y 速度原始值           |
| 4-7         | `GimbalAngles.Yaw`   | `float32` | little-endian               |
| 8-11        | `GimbalAngles.Pitch` | `float32` | little-endian               |
| 12          | `FireCode`           | `uint8`   | 开火/电容/Follow/Aim/Rotate |

此包不再携带 `SentryCmd`。`/ly/control/angles`、`/ly/control/vel`、 `/ly/control/firecode` 任一更新，都会更新 shadow 并发一包 `0x00`。

## 4. `SentryCommandFrame`（`0x01`，6B）

| byte offset | 字段             | 类型     | 说明                                                  |
| ----------- | ---------------- | -------- | ----------------------------------------------------- |
| 0           | `HeadFlag`       | `uint8`  | 固定 `0x21`                                           |
| 1           | `DownlinkTypeID` | `uint8`  | 固定 `0x01`                                           |
| 2-5         | `SentryCmd`      | `uint32` | little-endian，RM2026 V2.0 `0x0120 sentry_cmd` 命令字 |

`/ly/control/posture` 只更新姿态字段，会立即发送并按既有参数重发； `/ly/control/sentry_cmd` 按 `field_mask` 更新完整命令 shadow 后发送一包。

### 4.1 `SentryCmd` 位语义（RM2026 V2.0）

| bit   | ROS 字段                           | 说明                                                         |
| ----- | ---------------------------------- | ------------------------------------------------------------ |
| 0     | `confirm_free_revive`              | 确认免费复活                                                 |
| 1     | `confirm_immediate_revive`         | 确认兑换立即复活                                             |
| 2-12  | `exchange_projectile_allowance`    | 非远程兑换允许发弹量累计值，必须单调递增                     |
| 13-16 | `remote_projectile_exchange_count` | 远程兑弹请求次数，每次只加 1                                 |
| 17-20 | `remote_hp_exchange_count`         | 远程回血请求次数，每次只加 1                                 |
| 21-23 | `posture`                          | `1` 进攻、`2` 防御、`3` 移动、`4` 强化进攻、`5` 强化防御、`6` 强化移动 |
| 24    | `confirm_energy_activate`          | 确认能量机关进入正在激活状态                                 |
| 25-31 | -                                  | 保留，填 0                                                   |

## 5. `MapPathFrame`（`0x02`，107B）

此 frame 的 byte 2-106 是裁判 `0x0307 map_data_t` 原始 payload。下位机以自身机器人 ID/裁判发送流程封装 `0x0307`。

| byte offset | 字段                | 类型       | 说明                                     |
| ----------- | ------------------- | ---------- | ---------------------------------------- |
| 0           | `HeadFlag`          | `uint8`    | 固定 `0x21`                              |
| 1           | `DownlinkTypeID`    | `uint8`    | 固定 `0x02`                              |
| 2           | `Intention`         | `uint8`    | `1` 到点攻击、`2` 到点防守、`3` 移动到点 |
| 3-4         | `StartPositionX_dm` | `uint16`   | 小地图起点 x，dm                         |
| 5-6         | `StartPositionY_dm` | `uint16`   | 小地图起点 y，dm                         |
| 7-55        | `DeltaX_dm[49]`     | `int8[49]` | 相对上一点的 x 增量，dm                  |
| 56-104      | `DeltaY_dm[49]`     | `int8[49]` | 相对上一点的 y 增量，dm                  |
| 105-106     | `SenderId`          | `uint16`   | 裁判发送者 ID                            |

上位机只接受 `intention=1/2/3`。`MapPath.msg` 的 `delta_x_dm`、`delta_y_dm` 必须各恰好 49 个元素。

## 6. `CustomInfoFrame`（`0x03`，36B）

此 frame 的 byte 2-35 是裁判 `0x0308 custom_info_t` 原始 payload。下位机以裁判发送流程封装 `0x0308`，接收者仅可填己方允许的选手端 ID。

| byte offset | 字段             | 类型        | 说明                                       |
| ----------- | ---------------- | ----------- | ------------------------------------------ |
| 0           | `HeadFlag`       | `uint8`     | 固定 `0x21`                                |
| 1           | `DownlinkTypeID` | `uint8`     | 固定 `0x03`                                |
| 2-3         | `SenderId`       | `uint16`    | 裁判发送者 ID                              |
| 4-5         | `ReceiverId`     | `uint16`    | 裁判接收选手端 ID                          |
| 6-35        | `UserDataUtf16`  | `uint8[30]` | 完整 30B UTF-16 原始字节，按裁判规定字节序 |

`/ly/control/custom_info` 不做字符串编码转换；上游必须已提供 30B UTF-16 原始数据。

## 7. `SentryCoordinateFrame`（`0x04`，17B）

| byte offset | 字段             | 类型        | 说明                              |
| ----------- | ---------------- | ----------- | --------------------------------- |
| 0           | `HeadFlag`       | `uint8`     | 固定 `0x21`                       |
| 1           | `DownlinkTypeID` | `uint8`     | 固定 `0x04`                       |
| 2-3         | `X_cm`           | `int16`     | official-map x，cm，little-endian |
| 4-5         | `Y_cm`           | `int16`     | official-map y，cm，little-endian |
| 6-15        | `Reserved`       | `uint8[10]` | 填 0                              |
| 16          | `CRC8`           | `uint8`     | 对 byte 0-15 计算                 |

数据来源是 `/ly/bt/sentry_position`。上位机默认每 100ms 最多发一次；位置超过 2000ms 未刷新则停止发送。 CRC8 参数：poly `0x31`、init `0xFF`、非反射。

## 8. 旧协议迁移

| 旧布局                                  | 新布局                                       |
| --------------------------------------- | -------------------------------------------- |
| `0x00` 固定 17B，最后 4B 为 `SentryCmd` | `0x00` 改 13B，只保留速度/角度/FireCode      |
| `SentryCmd` 夹在控制包 byte 13-16       | 独立为 `0x01` 6B frame                       |
| `0x01` 是自身坐标                       | 自身坐标改为 `0x04`，内容与 CRC8 规则不变    |
| 无 `0x0307` / `0x0308` compact frame    | 新增 `0x02` 107B 路径、`0x03` 36B 自定义信息 |

此变更不保留旧下行解析兼容。下位机与上位机必须同时切换，否则旧 `0x01` 坐标包会被新固件当作 `SentryCommandFrame`，造成错误解析。
