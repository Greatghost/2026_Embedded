## 精读 steer_pos_kinematics 发现两处 bug（仅污染遥测，不影响驱动）
- 对照逆解 `steer_chassis_control`/`add_vector` 验证：`steer_pos_kinematics()`(steer.c:329) 与逆解不一致。
- Bug A（确定）：`tangent_angle_rad`(steer.c:335) 用 `{-45,45,-135,135}`，比逆解 `w_vector` 的 `{-135,135,-45,45}` 每个偏 90°；纯自转 1rad/s 时 `cos(steer-tangent)` 全为 0 → `yaw_v≈0`。
- Bug B（高度可疑）：平动分解 `vx+=speed*sin(θ)`, `vy+=speed*cos(θ)`(steer.c:357-358) 与 `add_vector` 的 `cos→x,sin→y` 互换；纯前进(0,1) 会反解成 (x_v=0,y_v=-1)。
- 该函数每 1ms 在 ChasisControlTask.c:43 调用，输出 x_v/y_v/yaw_v 经 GimbalSend.c 0x09A 回传云台——只影响云台用于瞄准补偿的速度量，不影响底盘驱动（驱动走 target_*+逆解+PID）。
- 已在文档 8.3.0 新增控制链路全景(mermaid 数据流图+步骤表+误区纠正)，并在 8.3.3 加 ⚠ 已知 bug 警示。未改代码。

## 舵轮控制逻辑梳理（用户提问）
- 确认控制链路：云台 CAN 下发 x/y(÷30) + yaw_motor_angle → get_sensors_info → steer_pos_kinematics(仅上报) → set_robot_speed(set_power→速度上限) → wheels_accel(receive→target) → main_control(按 control_mode_action 分流) → steer_chassis_control 逆解(平动+旋转向量叠加 + >90°翻转) → 3 个 PID(轮单环速度 / 舵 角度→速度双环+前馈) → wheels_power_limit(二次方程削电流) → execute_control(CAN1)。
- 关键纠正：w(yaw) 在 FOLLOW/SPEED_FOLLOW 由本板 turn_pid 用 error_angle 闭环算出，非云台直接给；仅 NOT_FOLLOW/CV_ROTATE 才直接用云台 w 或吃满 speed_yaw_max。已将完整链路图加入文档 8.3.0。
