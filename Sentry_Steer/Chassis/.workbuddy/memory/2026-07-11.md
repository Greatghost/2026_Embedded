## 项目架构文档编写
- 为舵轮哨兵底盘 STM32 控制板工程编写了 `项目架构文档.md`（位于 Chassis 根目录）。
- 关键事实（已核实）：
  - 当前机型 `#define ROBOT TIGER`（舵轮哨兵，`robot_config.h`）。
  - 底盘跟随 yaw 来自云台板 CAN 下发 `gimbal_receiver_pack1.yaw_motor_angle`，非本板 IMU；`ChasisEstimate_task`(INS) 当前构建已被注释，未运行。
  - 云台包解码 `Gimbal_msgs_Decode1/2` 由 CAN 接收中断 `Mylib/src/can_receive.c` 调用（Action_task 已注释）。
  - 主控 1kHz 循环：`ChasisControl_task` → get_sensors_info → steer_pos_kinematics → set_robot_speed → wheels_accel → main_control → wheels_power_limit → execute_control。
  - 功率双层：策略层 `PowerControlTask`(NingCapControl 设 set_power) + 执行层 `wheels_power_limit`(二次方程法削电流，舵轮优先×1.4)。
  - CAN1=电机，CAN2=云台通信/电容/SentryCmd；UART4=裁判系统；JudgeDataCanSend 在 GimbalTask(5ms) 统一调度回传。
- 未修改任何代码，仅读取与文档生成。

## 新增"重点调试模块详解"（文档第 9 节）
- 在 `项目架构文档.md` 末尾（参考文档 note 之前）新增 `## 9. 重点调试模块详解`，分四小节深度拆解：
  1. **裁判系统**：`Referee_UnpackFifoData` 六步状态机(SOF→LEN_L→LEN_H→SEQ→CRC8→CRC16)→`Referee_SolveFifoData` 按 cmd_id 分发；0x0301 雷达交互(0x0201/0202/0205)、0x0303 去重置 `is_robot_command_update`；UI 绘制函数齐备但 Refereetask 内 UI 块被注释；哨兵决策 `0x0301/data_cmd_id=0x0120/receiver=0x8080`，2Hz 上报。
  2. **云台通信**：接收链路 `can_receive.c` 中断按 0x150/0x151/0x15A 分发到 `Gimbal_msgs_Decode1/2` 与 SentryCmd 位提取；`GimbalReceivePack1` 8B 位域(yaw_motor_angle 是关键)；发送 `JudgeDataCanSend`(GimbalTask 5ms) 用 send_count 分频(20/10/50Hz) 发 0x094~0x09E；TypeID 7/8 的 `SentryInfoPack` 位重组、0x0303 由 is_robot_command_update 触发。
  3. **舵轮底盘**：`steer_pid_init` 零点/安装方向/PID；逆运动学 `steer_chassis_control`(跟随+平动+旋转向量叠加+>90°翻转优化+PID)；正运动学 `steer_pos_kinematics`；跟随角 `angle_z_err_get`+`getDir`(DM电机/90, TIGER SPEED_FOLLOW bias=31 否则-90)。
  4. **功率与电容**：双层(策略 `PowerControlTask`→`NingCapControl` 设 set_power；执行 `wheels_power_limit`→`PowerLimit` 二次方程法削电流，舵轮优先×1.4)；`NingCapControl` 缓冲能量+电容电压双三级状态机；`CapPowerSet` 依电容电压/超电模式返回。
- 每小节附"调试点提示"。始终未修改代码。
