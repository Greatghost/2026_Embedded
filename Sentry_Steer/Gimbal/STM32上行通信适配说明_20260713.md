# 底盘 CAN 协议变更 —— STM32 上行通信适配说明

> 2026-07-13 | 基于底盘 CAN 协议变更文档 | 本说明针对 STM32 USB 上行（→上位机）的改动

云台 CAN 接收层已完成改动（can_config.h / ChassisGet.h / ChassisGet.c / bsp_can.c），新数据已存入全局变量。本文档描述 **PC_Send 上行通信层**需要同步改什么。

---

## 一、已完成：新增数据已就绪

底盘 CAN 0x09F 的数据已存入全局变量，上行层可直接引用：

| 变量 | 类型 | 来源 | 说明 |
|------|------|------|------|
| `sentry_duration` | `SentryDuration_t` | CAN 0x09F (10Hz) | 6 种哨兵姿态剩余秒数 |
| `sentry_info_recv.sentry_info_2.bit15` | `uint16_t` | CAN 0x09C (已有) | 已更名为 `sentry_is_enhanced_posture`，数据已在 TypeID 7 中上行 |

> `SentryDuration_t` 结构体定义见 `application/inc/ChassisGet.h`，8 字节，字段名形如 `normal_attack_duration`、`enhanced_defend_duration` 等。

---

## 二、需要改动清单

### 改动 1：`application/inc/pc_serial.h` — 新增 TypeID 枚举

在 `PC_dataType_enum` 中新增：

```c
JUDGE_PC_DATA_SENTRY_DURATION = 10  // TypeID 10: 哨兵姿态时长 (0x020D扩展)
```

当前 TypeID 0~9 已占用，10 是第一个空闲编号。

---

### 改动 2：`application/inc/pc_serial.h` — 新增上行结构体

在各 TypeID 帧结构体区域（建议放在 `PCSendDataRobotCmd_t` 之后、`#pragma pack(pop)` 之前）：

```c
// TypeID 10: SentryDuration - 哨兵姿态时长 (0x020D扩展, CAN 0x09F)
typedef struct PCSendDataSentryDuration
{
    uint8_t start_flag;           // '!'
    uint8_t data_pack_type;       // = JUDGE_PC_DATA_SENTRY_DURATION = 10
    uint8_t normal_attack_duration;
    uint8_t normal_defend_duration;
    uint8_t normal_move_duration;
    uint8_t reserved_duration_1;
    uint8_t enhanced_attack_duration;
    uint8_t enhanced_defend_duration;
    uint8_t enhanced_move_duration;
    uint8_t reserved_duration_2;
    uint32_t reserved;            // 填充至 12 字节 payload
    uint8_t crc8;
} PCSendDataSentryDuration_t;  // sizeof == 15 bytes
```

> 布局：start_flag(1) + type_id(1) + 8 字节时长数据 + 4 字节保留 + crc8(1) = 15 字节。

---

### 改动 3：`application/src/pc_serial.c` — 新增发送函数

参照 `SendtoPCSentry()` / `SendtoPCRobotCmd()` 的模式：

```c
// TypeID 10: 发送哨兵姿态时长
void SendtoPCSentryDuration(unsigned char* buff)
{
    PCSendSentryDuration.start_flag = '!';
    PCSendSentryDuration.data_pack_type = JUDGE_PC_DATA_SENTRY_DURATION;
    PCSendSentryDuration.normal_attack_duration = sentry_duration.normal_attack_duration;
    PCSendSentryDuration.normal_defend_duration = sentry_duration.normal_defend_duration;
    PCSendSentryDuration.normal_move_duration = sentry_duration.normal_move_duration;
    PCSendSentryDuration.reserved_duration_1 = 0;
    PCSendSentryDuration.enhanced_attack_duration = sentry_duration.enhanced_attack_duration;
    PCSendSentryDuration.enhanced_defend_duration = sentry_duration.enhanced_defend_duration;
    PCSendSentryDuration.enhanced_move_duration = sentry_duration.enhanced_move_duration;
    PCSendSentryDuration.reserved_duration_2 = 0;
    PCSendSentryDuration.reserved = 0;
    PCSendSentryDuration.crc8 = 0;
    Append_CRC8_Check_Sum((unsigned char *)&PCSendSentryDuration, PC_SEND_BLOOD_SIZE);
    memcpy(buff, (void *)&PCSendSentryDuration, PC_SEND_BLOOD_SIZE);
}
```

以及对应的全局变量定义：

```c
PCSendDataSentryDuration_t PCSendSentryDuration;
```

---

### 改动 4：`application/src/pc_serial.c` `SendtoPC()` — 新增分发分支

在 `else if(data_type == JUDGE_PC_DATA_ROBOT_COMMAND)` 之后：

```c
else if(data_type == JUDGE_PC_DATA_SENTRY_DURATION)
{
    SendtoPCSentryDuration(SendToPC_Buff);
}
```

---

### 改动 5：`Task/src/GimbalTask.c` `PC_Send()` — 新增发送频率

在 `PC_Send()` 中增加 TypeID 10 的发送调度。建议 **10Hz**，选一个空闲的 index 槽位：

当前 50 分频（10Hz）已占用槽位：1(Judge), 5(Sentry), 13(Extended), 15(Blood2), 25(Bullet), 37(Pos), 50*n+1(Blood1)

建议使用 `index % 50 == 45`（10Hz，空闲）：

```c
// 新增: TypeID 10 哨兵姿态时长发送 (10Hz)
if (index % 50 == 45)
{
    SendtoPC(JUDGE_PC_DATA_SENTRY_DURATION);
}
```

---

### 不改动项

| TypeID | 帧 | 说明 |
|--------|-----|------|
| 7 (Sentry) | `PCSendDataSentry_t` | `sentry_info_2` 已在发送，bit15 语义变更无需改动上行代码，仅上位机端重新解释即可 |
| 1 (Judge) | `PCSendDataJudge_t` | `Enemy_outpost` 数据源变更在下层（CAN 接收），上行结构和发送逻辑不变 |
| 2/3 (Blood) | `PCSendDataBlood_1/2` | `ID8` 基地血量数据源变更在下层，上行结构不变 |

## 二、TypeID 11：伤害值差（CAN 0x0A0）—— 新增

### 改动 1：`application/inc/pc_serial.h` — 新增 TypeID 枚举

```c
JUDGE_PC_DATA_DAMAGE_DIFF = 11  // TypeID 11: 伤害值差 (0x0003扩展)
```

### 改动 2：`application/inc/pc_serial.h` — 新增上行结构体

```c
// TypeID 11: DamageDiff - 伤害值差 (0x0003扩展, CAN 0x0A0)
typedef struct PCSendDataDamageDiff
{
    uint8_t start_flag;           // '!'
    uint8_t data_pack_type;       // = JUDGE_PC_DATA_DAMAGE_DIFF = 11
    int16_t damage_difference;    // 伤害值差 (己方HP总和 − 敌方HP总和)，正值=领先
    uint8_t  reserve[6];          // 补零至8字节
    uint32_t reserved;            // 填充至12字节payload
    uint8_t crc8;
} PCSendDataDamageDiff_t;  // sizeof == 15 bytes
```

### 改动 3：`application/src/pc_serial.c` — 新增全局变量 + 发送函数

```c
PCSendDataDamageDiff_t PCSendDamageDiff;

void SendtoPCDamageDiff(unsigned char* buff)
{
    PCSendDamageDiff.start_flag = '!';
    PCSendDamageDiff.data_pack_type = JUDGE_PC_DATA_DAMAGE_DIFF;
    PCSendDamageDiff.damage_difference = damage_diff.damage_difference;
    memset(PCSendDamageDiff.reserve, 0, 6);
    PCSendDamageDiff.reserved = 0;
    PCSendDamageDiff.crc8 = 0;
    Append_CRC8_Check_Sum((unsigned char *)&PCSendDamageDiff, PC_SEND_BLOOD_SIZE);
    memcpy(buff, (void *)&PCSendDamageDiff, PC_SEND_BLOOD_SIZE);
}
```

### 改动 4：`application/src/pc_serial.c` `SendtoPC()` — 新增分发分支

```c
else if(data_type == JUDGE_PC_DATA_DAMAGE_DIFF)
{
    SendtoPCDamageDiff(SendToPC_Buff);
}
```

### 改动 5：`Task/src/GimbalTask.c` `PC_Send()` — 新增发送频率

建议 `index % 50 == 33`（10Hz，空闲槽位）：

```c
if (index % 50 == 33)
{
    SendtoPC(JUDGE_PC_DATA_DAMAGE_DIFF);
}
```
