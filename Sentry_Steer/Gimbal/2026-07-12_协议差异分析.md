## 一、下行（上位机 → 下位机）

### 1.1 总览：分包策略完全重构

| 维度 | 当前代码 | 新协议 | 影响 |
|------|---------|--------|------|
| 编号体系 | 单一 `TypeID` | `DownlinkTypeID` 独立编号空间 | 需整体切换 |
| 帧数量 | 2 种 (0x00控制, 0x01坐标) | **5 种** (0x00~0x04) | 新增 3 种帧 |
| 解析方式 | 固定 17B 解析 | 先读 byte1 再按 ID 读可变长度 | **struct 需重写** |

### 1.2 逐帧对比

#### `DownlinkTypeID=0x00` — 控制帧

| 项目 | 当前 `PCRecvData_1` | 新 `GimbalControlFrame` | 变更 |
|------|---------------------|------------------------|------|
| 总长度 | **18B** | **13B** | ↓ 5B |
| byte 0 | Head `'!'` | Head `'!'` | 不变 |
| byte 1 | `TypeID` = 0x00 | `DownlinkTypeID` = 0x00 | 不变 |
| byte 2 | `Aim_v_x` (int8) | `Velocity.X` (int8) | 不变 |
| byte 3 | `Aim_v_y` (int8) | `Velocity.Y` (int8) | 不变 |
| byte 4-7 | `Aim_Yaw` (float) | `GimbalAngles.Yaw` (float) | 不变 |
| byte 8-11 | `Aim_Pitch` (float) | `GimbalAngles.Pitch` (float) | 不变 |
| byte 12 | `FireCode` (uint8) | `FireCode` (uint8) | 不变 |
| byte 13-16 | ~~`SentryCmd` (uint32)~~ | — | **删除** |
| byte 17 | ~~`tail` (0x00)~~ | — | **删除** |

> **关键变更**: `SentryCmd` 不再夹在控制帧里，独立为新 0x01。

#### `DownlinkTypeID=0x01` — SentryCmd（原坐标帧被挤走）

| 项目 | 当前 `SentryCoord_t` | 新 `SentryCommandFrame` | 变更 |
|------|---------------------|------------------------|------|
| 总长度 | 18B | **6B** | ↓ 12B |
| byte 0 | head `0x21` | `HeadFlag` `0x21` | 不变 |
| byte 1 | type_id = **0x01** | `DownlinkTypeID` = **0x01** | **语义完全不同** |
| byte 2-5 | x_cm, y_cm (int16 ×2) | **`SentryCmd` (uint32)** | **完全替换** |
| byte 6-15 | reserved[10] | — | 删除 |
| byte 16 | CRC8 | — | 删除（6B 太短无 CRC） |

> **危险**: 当前代码的 0x01=坐标帧，新协议 0x01=SentryCmd。不兼容！旧坐标数据被解析为命令字会导致不可预期行为。

#### `DownlinkTypeID=0x02` — 地图路径帧：**全新**

| 项目 | 内容 |
|------|------|
| 总长度 | **107B** |
| 用途 | 小地图 0x0307 map_data_t 原样转发 |
| 字段 | Intention(1B) + StartPos(4B) + DeltaX[49](49B) + DeltaY[49](49B) + SenderId(2B) |

当前代码：**不存在**，需新增接收和 CAN 转发。

#### `DownlinkTypeID=0x03` — 自定义信息帧：**全新**

| 项目 | 内容 |
|------|------|
| 总长度 | **36B** |
| 用途 | 0x0308 custom_info_t 原样转发 |
| 字段 | SenderId(2B) + ReceiverId(2B) + UserDataUtf16(30B) |

当前代码：**不存在**，需新增。

#### `DownlinkTypeID=0x04` — 哨兵坐标帧：**原 0x01 改名**

| 项目 | 当前 `SentryCoord_t` (TypeID=0x01) | 新 `SentryCoordinateFrame` (0x04) | 变更 |
|------|-----------------------------------|----------------------------------|------|
| 总长度 | 18B | **17B** | ↓ 1B |
| byte 0-1 | head + type_id | HeadFlag + DownlinkTypeID | type_id 从 0x01→0x04 |
| byte 2-5 | x_cm, y_cm | X_cm, Y_cm | 不变 |
| byte 6-15 | reserved[10] | Reserved[10] | 不变 |
| byte 16 | `crc8` | `CRC8` (poly=0x31, init=0xFF) | 不变 |

> 实际上是**原 0x01 坐标帧搬家到 0x04**，去掉了 `crc8` 字段占用的 1 字节 → 从 18B 变为 17B。

### 1.3 SentryCmd 位语义变更

| bit | 当前代码 | 新协议 V2.0 | 变更 |
|-----|---------|------------|------|
| 21-23 | posture bit21-22 (1-3), bit23=confirm_energy | posture **bit21-23** (1-6 种姿态) | 扩展 1 位 |
| 24 | — | confirm_energy_activate | 从 bit23 移到 bit24 |

新增姿态: `4`=强化进攻, `5`=强化防御, `6`=强化移动（当前代码只识别 1/2/3）。

影响文件: [pc_serial.c:166](application/src/pc_serial.c#L166) `posture_from_cmd` 提取逻辑。

## 二、上行（下位机 → 上位机）

### 2.1 TypeID=6 (EXTENDED) — 字段语义变更

| byte offset | 当前代码 | 新协议 | 变更 |
|-------------|---------|--------|------|
| 2-3 | ~~`UWB_yaw_10`~~ 4B 的一部分 | **`DamageDifference`** (int16) | **完全替换** |
| 备注 | 含有 `sentry_posture` | 姿态只走 TypeID 7 的 0x020D，不再走 TypeID 6 | 去重 |

`DamageDifference` 来源: 裁判 0x0003 `game_robot_HP_t` byte offset 8, 语义=己方全队总伤害-对方全队总伤害。

### 2.2 TypeID=10 — 全新上行帧

| 项目 | 内容 |
|------|------|
| 总长度 | **15B**（1 head + 1 type + 12 data + 1 CRC8） |
| byte 0-7 | `sentry_info_3` (0x020D 扩展 8B) |
| byte 8-9 | `ally_outpost_HP` (uint16, 0x0003 己方前哨血量) |
| byte 10-11 | `enemy_outpost_HP` (uint16, 0x0003 敌方前哨血量) |

> 约束: 暂时拿不到 0x0003 前哨血量时**暂停发送**（不发 0 占位），让上位机 fallback 到 TypeID=1 的 GameCode×25。

当前代码：**不存在**，需新增结构体 `PCSendDataV2_10` 和发送函数。

## 三、变更汇总

### 3.1 下位机需要改动的文件

| 文件 | 改动内容 | 优先级 |
|------|---------|--------|
| [pc_serial.h](application/inc/pc_serial.h) | 新增 5 种下行帧结构体 + 上行 TypeID=10 结构体 | 🔴 高 |
| [pc_serial.c](application/src/pc_serial.c) | `PCReceive()` 按 DownlinkTypeID 分发；`SendtoPC()` 新增 TypeID=10 case；TypeID=6 替换 DamageDifference | 🔴 高 |
| [GimbalTask.c](Task/src/GimbalTask.c) | 下行 SentryCmd 不再从控制帧提取，改为独立 0x01 帧解析 | 🔴 高 |
| CAN 转发 | 新增 0x0307/0x0308 转发逻辑；SentryCmd 转发来源改为 0x01 帧 | 🟡 中 |
| Uplink 调度 | TypeID=10 调度（来源 0x0003 有数据时才发） | 🟡 中 |

### 3.2 破坏性变更

| 变更 | 影响 |
|------|------|
| 下行 0x00 从 18B→13B | 上位机/下位机**必须同时切换** |
| 下行 0x01 从坐标→SentryCmd | 旧上位机 + 新下位机 = SentryCmd 被当坐标, 坐标被当 SentryCmd |
| SentryCmd 姿态 bit21-23 | 旧代码只读 bit21-22, 新协议需要读 3bit |
| 下行无 CRC/无 tail | 帧完整性完全靠 USB CDC 保证 |

### 3.3 不影响的部分

- TypeID=0~5, 7~9 的上行帧结构不变
- `PC_SENDBUF_SIZE` = 15B 上行帧格式不变（1 head + 1 type + 12 data + 1 CRC8）
- 上行 CRC8 算法不变
