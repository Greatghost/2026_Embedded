# 2026-07-14 工作记录

## 诊断：手动 RC 模式下底盘移动左右反向

用户反馈换大 Yaw 电机 + 重标 `GIMBAL_BIG_YAW_ZERO_POINT`(gimbal_config.h:148) 后，遥控器手动控制模式下底盘左右移动反向。

代码核查结论（未改代码，仅读）：
- 大 Yaw 反馈角 `gyro_yaw_angle = INS.YawTotalAngle`（Gimbal.c:349），来自 IMU，**与电机/零点无关**。故云台自身瞄准闭环不会因换电机而反向或失稳（方向由 `GIMBAL_BIG_YAW_MOTOR_SIGN` 与电机力矩方向决定）。
- `GIMBAL_BIG_YAW_ZERO_POINT` 仅在 `ChassisSend.c:53` 一处使用：`yaw_motor_angle = (DM_Big_Yaw_Motor.P_Receive - ZERO_POINT)*90`，发给底盘(CAN 0x150)。底盘用此角在跟随模式旋转速度矢量。
- **最可能根因**：新电机的编码器(P_Receive)计数方向与旧电机相反 → 上式斜率变号 → 发给底盘的 `yaw_motor_angle` 符号翻转 → 底盘在跟随模式下左右镜像。ZERO_POINT 仅是截距，无法翻转斜率；真正需要的是给电机编码器路径加一个符号宏（类似 `GIMBAL_BIG_YAW_GYRO_SIGN`）。
- 遥控器映射 `DJIRemoteUpdate`（ChassisSolver.c:525）未改：左摇杆→`target_big_yaw_angle`，右摇杆→`chassis_speed_x/y`，无符号翻转，故"遥控逻辑"假设概率低。
- 若用户实际指"云台 yaw 瞄准左右反"，则是 `GIMBAL_BIG_YAW_MOTOR_SIGN`(gimbal_config.h:165) 与新手力矩方向不匹配，翻转该宏即可（安全，因反馈为陀螺）。

待办：建议用户用 Ozone 同时观察 `INS.YawTotalAngle` 与 `DM_Big_Yaw_Motor.P_Receive` 确认编码器方向是否翻转，以定位是底盘镜像还是云台瞄准反向。

## 已修复（修法 A）：新增编码器方向符号宏

用户确认按修法 A 改动。已实际修改两处：
- `config/gimbal_config.h`：在 `GIMBAL_BIG_YAW_ZERO_POINT`(148) 后新增
  `#define GIMBAL_BIG_YAW_ENC_SIGN  -1.0f`（默认 -1.0f 翻转发给底盘的 yaw 角）。
- `application/src/ChassisSend.c:53`：`yaw_motor_angle = (P_Receive - ZERO_POINT)*90 * GIMBAL_BIG_YAW_ENC_SIGN`。

注意：
- 此改动**只影响发给底盘的 yaw 角**，**不动**云台自身的 IMU 反馈/力矩环（`GIMBAL_BIG_YAW_MOTOR_SIGN` 未碰），故不会让云台旋转反向。
- 若实测底盘反而更糟（诊断方向有误），把该宏置回 `1.0f` 即恢复。
- 未触碰 `GIMBAL_BIG_YAW_MOTOR_SIGN`（那是云台瞄准方向的旋钮，改了会弄反还能正常开的云台）。
