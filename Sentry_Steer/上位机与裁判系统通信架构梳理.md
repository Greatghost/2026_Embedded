# 哨兵机器人 上位机与裁判系统通信架构梳理

> **适用机型**: TIGER（舵轮哨兵底盘，`#define ROBOT TIGER`）
> **梳理范围**: USB CDC 上行/下行帧、CAN2 双机通信、裁判系统 UART 串口、运动学自解算数据回传
> **最后更新**: 2026-07-22
> **本文档不修改任何代码**，仅梳理现有工程结构与数据流向

---

## 0. 整体架构总览

### 0.1 三方通信拓扑

```
┌─────────┐  USB CDC    ┌─────────┐  CAN1↔CAN2  ┌─────────┐  UART4     ┌─────────┐
│   PC    │ ───────────► │  云台板  │ ───────────► │  底盘板  │ ─────────► │ 裁判系统 │
│ (上位机) │  上行15B/下行 │ Gimbal  │  8B CAN帧    │ Chassis │  裁判协议  │ Referee │
│         │ ◄─────────── │         │ ◄─────────── │         │ ◄─────────│         │
└─────────┘              └─────────┘              └─────────┘           └─────────┘
```

### 0.2 物理总线分配

| 总线 | 用途 | 关键 ID |
|------|------|---------|
| **云台 CAN1** | 底盘→云台 裁判/速度/坐标等回传 | 0x094~0x0A3, 0x160 |
| **云台 CAN1** | 云台→底盘 命令转发 | 0x15A, 0x152, 0x153 |
| **云台 CAN2** | 云台电机（大yaw/pitch/摩擦轮/拨弹） | 0x10/0x11/0x201/0x202/0x204/0x166 |
| **底盘 CAN1** | 底盘电机（3508轮/6020舵） | 0x201~0x204, 0x205~0x208 |
| **底盘 CAN2** | 云台通信 + 电容板 + 哨兵指令 | 0x150/0x151/0x051/0x15A/0x152/0x153 |
| **云台 USB CDC** | PC 通信（虚拟串口） | 上行 15B 帧 / 下行变长帧 |
| **底盘 UART4** | 裁判系统串口（115200, DMA 4096B 环形缓冲） | RM V2.0 协议 |

### 1.2 下行 TypeID 详解

#### TypeID 0x00 — GimbalControlFrame_t (13B)

**结构** (`pc_serial.h:139-160`):
```c
typedef struct GimbalControlFrame {
    uint8_t  start_flag;      // 0x21
    uint8_t  data_pack_type;  // 0x00
    int16_t  yaw;             // 云台目标yaw(0.01°)
    int16_t  pitch;           // 云台目标pitch(0.01°)
    int16_t  nav_speed_x;     // 底盘x速度(mm/s)
    int16_t  nav_speed_y;     // 底盘y速度(mm/s)
    FireCode_t fire_code;     // 射击/模式控制位域(2B)
    uint8_t  crc8;
} GimbalControlFrame_t;  // sizeof=13
```

**数据流向**:
1. 校验角度合法性 `PCControlAnglesValid()`
2. 用奇偶序列锁写入 `pc_control_shadow`（主路径）
3. 同步写 legacy 镜像（部分为死代码，见第 8 节）
4. 消费者通过 `PCControlGetSnapshot()` 读取快照：
   - `GimbalTask.c:85` → 云台 yaw/pitch 目标 + 前馈
   - `ChassisSolver.c:73` → 底盘模式/速度
   - `ShootTask.c:322` → 射击判定

#### TypeID 0x05 — GimbalTrajectoryFrame_t (26B)

MPC 轨迹原子帧，写入 `pc_control_shadow` 的 `yaw/pitch/yaw_omega/pitch_omega/yaw_alpha/pitch_alpha`。
通过 `PCControlDynamicsSanitize` 限幅（±2000 dps / ±50000 dps²）。
被 `GimbalTask.c:128-131` 前馈控制使用。

#### TypeID 0x01 — SentryCommandFrame_t (6B)

**结构** (`pc_serial.h:162-166`):
```c
typedef struct SentryCommandFrame {
    uint8_t  start_flag;
    uint8_t  data_pack_type;  // 0x01
    uint32_t sentry_cmd;      // 命令字(含bit21-23 posture)
    uint8_t  crc8;
} SentryCommandFrame_t;  // sizeof=6
```

**数据流向**:
- 本地: 提取 `posture = (cmd >> 21) & 0x07`（3bit, 值1-6）写入 `current_posture`
- CAN 转发: `Can1SendSentryCmd(cmd)` → CAN 0x15A → 底盘

#### TypeID 0x02 — MapPathFragment_t (64B ×2 分片)

两段 64B 分片 → 重组为 105B `map_data_t` payload。
`MapPath_OnFragment()` (`pc_serial.c:721-784`) 做 CRC16 校验、序列匹配、超时清空、intention 校验（必须 1/2/3）。
重组成功后调用 `Can1SendMapPath()` → CAN 0x152 ×15 帧。

#### TypeID 0x03 — CustomInfoFrame_t (36B)

直接转发 34B payload: `Can1SendCustomInfo(PCbuffer + 2)` → CAN 0x153 ×5 帧。

#### TypeID 0x04 — SentryCoordinateFrame_t (17B)

CRC8 校验后写入 `sentry_position_x_cm` / `sentry_position_y_cm`。
被 `ChassisSend.c:62 Pack_SentryCoord()` 消费，通过 CAN 发给底盘。

### 1.3 奇偶序列锁机制（Seqlock）

**位置**: `pc_serial.c:116-220`

**生产端**（USB CDC ISR 上下文）:
1. `pc_control_sequence++` → 序号变奇数（"写锁 ON"）
2. `__DMB()` 内存屏障
3. 写 `pc_control_shadow` 各字段
4. 更新 `pc_control_last_rx_tick` / `pc_control_received`
5. `__DMB()`
6. `pc_control_sequence++` → 序号变偶数（"写锁 OFF"）

**消费端**（`PCControlGetSnapshot` 在控制任务上下文）:
1. 读 `sequence_start`，若为奇数 → `continue`（写者正在改，跳过）
2. 若为偶数 → `__DMB()` → 整块拷贝 shadow → `__DMB()`
3. 再读 `sequence_end`，若 `sequence_start == sequence_end` 且仍为偶数 → 快照有效
4. 否则回到 for 头部重读
5. 最后根据 `last_rx_tick` 判断在线状态（200ms 超时 `PC_CONTROL_TIMEOUT_MS`）

**调用方**:
- `GimbalTask.c:85` `Gimbal_PC_Target_Update`
- `ChassisSolver.c:73` `PCStateControl`
- `ShootTask.c:322` `Shoot_Autoaim_Cal`
- `ChassisSolver.c:603` `DJIRemoteUpdate`（仅在线状态判断）
- `PCControlIsOnline()` (`pc_serial.c:222`) 被 `ChassisSolver.c:181 DJIKeyMouseUpdate` 调用

### 2.3 裁判系统帧格式（RM V2.0）

所有底盘发送到裁判系统的帧统一格式:
```
[0]     SOF = 0xA5
[1..2]  data_length (uint16 LE)
[3]     seq (帧序列号)
[4]     CRC8 (覆盖前5字节)
[5..6]  cmd_id (uint16 LE)
[7..N]  data (data_length 字节)
[N+1..N+2] CRC16 (覆盖全帧)
```
