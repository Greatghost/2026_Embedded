# 云台 ↔ 上位机通信协议总览

Updated: 2026-07-19

本文档总结云台板与上位机之间通过 USB CDC 串口传输的所有**上行帧**（云台→上位机）与**下行帧**（上位机→云台）的完整格式。

- 通信端口：USB CDC（虚拟串口），字节流，需自行拆包/粘包处理
- 字节序：所有多字节整数 **little-endian**
- 浮点：IEEE 754 single-precision（float32 LE）
- 字节对齐：所有 frame 使用 `#pragma pack(push, 1)` 严格 1 字节对齐
- CRC8 参数：poly = `0x31`，init = `0xFF`，非反射，覆盖 byte 0 至 (N-2)
- 涉及代码：
  - 结构体定义：[`Gimbal/application/inc/pc_serial.h`](../../Gimbal/application/inc/pc_serial.h)
  - 收发实现：[`Gimbal/application/src/pc_serial.c`](../../Gimbal/application/src/pc_serial.c)
  - 0x0204/0x0101 子结构体：[`Gimbal/config/receive_data.h`](../../Gimbal/config/receive_data.h)
  - CAN 透传子结构体：[`Gimbal/application/inc/ChassisGet.h`](../../Gimbal/application/inc/ChassisGet.h)

## 一、上行帧总表（云台 → 上位机）

所有上行帧**统一长度 15 字节**，布局固定：

```
+--------+----------+----------------+--------+
| byte 0 | byte 1   | byte 2 .. 13  | byte 14|
+--------+----------+----------------+--------+
|  0x21  | TypeID   |  12B Data     |  CRC8  |
+--------+----------+----------------+--------+
```

`'!'` (0x21) 是帧头；TypeID 区分 12 种数据包；CRC8 覆盖 byte 0-13。所有上行帧共用 `SendToPC_Buff`，由 `SendtoPC(uint8_t data_type)` 统一调度，经 `CDC_Transmit_FS` 发送。

| TypeID | 枚举 | 名称 | 结构体 | 数据来源 |
|--------|------|------|--------|---------|
| 0 | `USUAL_PC_DATA` | 常规姿态数据 | `PCSendData` | 云台 IMU + 底盘电容/弹量 |
| 1 | `JUDGE_PC_DATA` | 比赛信息 | `PCSendDataJudge` | 裁判 0x0001/0x0003 等 |
| 2 | `JUDGE_PC_DATA_BLOOD_1` | 友方血量 | `PCSendDataBlood_1` | 裁判 0x098 |
| 3 | `JUDGE_PC_DATA_BLOOD_2` | 敌方血量 | `PCSendDataBlood_2` | 裁判 0x098 |
| 4 | `JUDGE_PC_DATA_RFID_BUFF` | Buff+RFID | `PCSendDataRFIDAndBuff_t` | 裁判 0x0204 |
| 5 | `JUDGE_PC_DATA_POS` | 友敌位置轮询 | `PCSendDataPosition_t` | 裁判位置 + 0x0207 弹速 |
| 6 | `JUDGE_PC_DATA_EXTENDED` | 扩展数据 | `PCSendDataExtended_t` | UWB角度 + 伤害差 + 舵角/底盘速度 (对齐上位机 ChassisData) |
| 7 | `JUDGE_PC_DATA_SENTRY_DATA` | 哨兵信息 | `PCSendDataSentry_t` | 裁判 0x020D + 0x0207 弹速 |
| 8 | `JUDGE_PC_DATA_BULLET_DATA_AND_RFID2` | 弹量扩展 | `PCSendDataBulletAndRfid2_t` | 裁判 0x0207 + 0x0208 + 0x0209 |
| 9 | `JUDGE_PC_DATA_ROBOT_COMMAND` | 小地图下发指令 | `PCSendDataRobotCmd_t` | 裁判 0x0303 (CAN 0x09E) |
| 10 | `JUDGE_PC_DATA_SENTRY_DURATION` | 哨兵姿态时长 | `PCSendDataSentryDuration_t` | 裁判 0x020D 扩展 (CAN 0x09F) + 0x0A3 前哨站HP原始值 |
| 11 | `JUDGE_PC_DATA_GIMBAL_DYNAMICS` | 云台角速度/角加速度 | `PCSendDataGimbalDynamics_t` | 云台 IMU |

## 二、下行帧总表（上位机 → 云台）

下行帧**长度不固定**，由 byte 1 的 `DownlinkTypeID` 决定。所有下行帧 byte 0 都是 `0x21`。

USB CDC 是字节流，由 `PCStreamReceive` 负责拆包/粘包，再派发到 `PCReceive`。最大下行帧是 0x02 的 64B 分片帧。

| DownlinkTypeID | 名称 | 总长度 | 结构体 | 备注 |
|----------------|------|--------|--------|------|
| `0x00` | `GimbalControlFrame` | 13B | `GimbalControlFrame_t` | 常规控制帧 |
| `0x01` | `SentryCommandFrame` | 6B | `SentryCommandFrame_t` | 哨兵命令字 |
| `0x02` | `MapPathFragment` | 64B | `MapPathFragment_t` | 小地图路径分片 |
| `0x03` | `CustomInfoFrame` | 36B | `CustomInfoFrame_t` | 自定义信息 |
| `0x04` | `SentryCoordinateFrame` | 17B | `SentryCoordinateFrame_t` | 哨兵自身坐标 |
| `0x05` | `GimbalTrajectoryFrame` | 26B | `GimbalTrajectoryFrame_t` | MPC 轨迹帧 |

宏定义：

```c
#define PC_DOWNLINK_CONTROL      0x00
#define PC_DOWNLINK_SENTRY_CMD   0x01
#define PC_DOWNLINK_MAP_PATH     0x02
#define PC_DOWNLINK_CUSTOM_INFO  0x03
#define PC_DOWNLINK_COORD        0x04
#define PC_DOWNLINK_TRAJECTORY   0x05
#define PC_CONTROL_TIMEOUT_MS    200U  // 0x00 控制帧超时
```

### 2.1 DownlinkTypeID 0x00：`GimbalControlFrame`（13B）

常规控制帧，承载底盘速度、云台角度目标、FireCode 位域。`/ly/control/angles`、`/ly/control/vel`、`/ly/control/firecode` 任一更新都会发一包 0x00。

| byte offset | 字段 | 类型 | 说明 |
|-------------|------|------|------|
| 0 | `head` | `uint8` | 固定 `0x21` |
| 1 | `type_id` | `uint8` | 固定 `0x00` |
| 2 | `vel_x` | `int8` | 底盘 x 速度原始值（解析时 ÷50） |
| 3 | `vel_y` | `int8` | 底盘 y 速度原始值（解析时 ÷50） |
| 4-7 | `yaw` | `float32 LE` | Yaw 目标角度（deg） |
| 8-11 | `pitch` | `float32 LE` | Pitch 目标角度（deg） |
| 12 | `fire_code` | `uint8` | FireCode 位域（详见 2.1.1） |

#### 2.1.1 `fire_code` 位域（uint8）

| bit | 字段 | 位数 | 说明 |
|-----|------|------|------|
| 0-1 | `FireStatus` | 2 | 开火状态，**所有位反转表示开火**：`0b00` ↔ `0b11` 切换 |
| 2-3 | `CapState` | 2 | 电容状态：`00` 不用 / `01` 轻度 / `10` 重度 |
| 4 | `FollowMode` | 1 | 跟随模式：`1` 启用（→ `FOLLOW_GIMBAL`），`0` 禁用 |
| 5 | `AimMode` | 1 | 辅瞄模式：`1` 启用，`0` 禁用 |
| 6-7 | `Rotate` | 2 | 小陀螺档位：`0` 无速 / `1` 低速 / `2` 中速 / `3` 高速 |

解析代码（`pc_serial.c:272-276`）：

```c
pc_control_shadow.shoot_state  = frame.fire_code & 0x03U;
pc_control_shadow.cap_state     = (frame.fire_code >> 2) & 0x03U;
pc_control_shadow.follow_mode   = (frame.fire_code >> 4) & 0x01U;
pc_control_shadow.aim_mode      = (frame.fire_code >> 5) & 0x01U;
pc_control_shadow.rotate_state  = (frame.fire_code >> 6) & 0x03U;
```

#### 2.1.2 FollowMode 与底盘模式映射

在 `ChassisSolver.c::PCStateControl()` 中：

| FollowMode | RotateState | 触发底盘模式 | chassis_speed_w |
|------------|-------------|-------------|-----------------|
| 1 | 任意 | `FOLLOW_GIMBAL` | 0 |
| 0 | 0 | `NOT_FOLLOW_GIMBAL` | 0 |
| 0 | 1 | `CV_ROTATE` | 0.5 × MAX_YAW_SPEED |
| 0 | 2 | `CV_ROTATE` | 0.75 × MAX_YAW_SPEED |
| 0 | 3 | `CV_ROTATE` | 1.0 × MAX_YAW_SPEED |

**FollowMode 优先于 Rotate**。控制帧超过 200ms 未更新视为离线。

## 三、关键实现细节

### 3.1 帧分发与原子快照

下行帧经 `PCStreamReceive()` 字节流拆包后调用 `PCReceive(PCbuffer, length)`，按 byte 1 (`type_id`) 派发：

| type_id | 处理 |
|---------|------|
| 0x00 | 写入 `pc_control_shadow`（带奇偶序列锁）+ 旧接口镜像（`pc_yaw`、`NAV_cmd`、`Shoot_Cmd` 等） |
| 0x01 | 提取 posture，调用 `Can1SendSentryCmd(cmd)` |
| 0x02 | `MapPath_OnFragment()` 重组，成功后 `Can1SendMapPath()` |
| 0x03 | `Can1SendCustomInfo()` |
| 0x04 | CRC8 校验通过后写入 `sentry_position_x_cm/y_cm` |
| 0x05 | 写入 `pc_control_shadow`（覆盖 0x00 的角度/速度/加速度） |

### 3.2 PCControlSnapshot 原子快照

`PCControlSnapshot_t` 是控制任务读取上位机命令的统一入口，使用**奇偶序列锁 + DMB 屏障**保证读取到完整一帧：

```c
typedef struct {
    float yaw, pitch;
    float yaw_omega, pitch_omega, yaw_alpha, pitch_alpha;
    float nav_speed_x, nav_speed_y, nav_speed_w;
    uint8_t shoot_state, cap_state;
    uint8_t follow_mode;   // FireCode bit4
    uint8_t aim_mode;      // FireCode bit5
    uint8_t rotate_state;   // FireCode bit6-7
} PCControlSnapshot_t;
```

访问 API：

- `PCControlGetSnapshot(snapshot)` —— 返回 1=在线且快照有效，0=离线
- `PCControlIsOnline()` —— 仅返回在线状态

### 3.3 CRC8 参数（统一）

- 多项式：`0x31`
- 初值：`0xFF`
- 非反射（input/output 都不反转）
- 覆盖范围：byte 0 至 (N-2)，最后 1B 装填 CRC

实现：`Append_CRC8_Check_Sum()`（写）+ `Verify_CRC8_Check_Sum()`（校验）。

### 3.4 编译期尺寸校验

`pc_serial.h` 用以下 typedef 在编译期硬约束协议尺寸：

```c
typedef char GimbalControlFrameSizeCheck   [(sizeof(GimbalControlFrame_t)       == 13U) ? 1 : -1];
typedef char GimbalTrajectoryFrameSizeCheck[(sizeof(GimbalTrajectoryFrame_t)    == 26U) ? 1 : -1];
typedef char GimbalDynamicsFrameSizeCheck  [(sizeof(PCSendDataGimbalDynamics_t) == 15U) ? 1 : -1];
typedef char MapPathFragmentSizeCheck      [(sizeof(MapPathFragment_t)          == 64U) ? 1 : -1];
```

尺寸不匹配会直接编译失败。

### 3.5 旧协议迁移说明（2026-07-11）

| 旧布局 | 新布局 |
|--------|--------|
| `0x00` 固定 17B，最后 4B 为 `SentryCmd` | `0x00` 改 13B；MPC 轨迹另用 `0x05` |
| `SentryCmd` 夹在 byte 13-16 | 独立为 `0x01` 6B frame |
| `0x01` 是自身坐标 | 自身坐标改为 `0x04`，内容与 CRC8 规则不变 |
| 无 `0x0307` / `0x0308` compact frame | 新增 `0x02` 路径、`0x03` 自定义信息 |

此变更**不保留旧下行解析兼容**，下位机与上位机必须同时切换。
