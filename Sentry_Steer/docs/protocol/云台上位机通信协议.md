# 云台上位机通信协议

***

## 一、通用约定

| 项目   | 说明                                      |
| ---- | --------------------------------------- |
| 物理层  | USB CDC 虚拟串口，**字节流**，无消息边界，需自行处理拆包 / 粘包 |
| 帧头   | 所有帧 byte 0 固定为 `0x21`（字符 `'!'`）         |
| 字节序  | 所有多字节整数 **little-endian**               |
| 浮点   | IEEE 754 single-precision（float32 LE）   |
| 字节对齐 | 所有帧严格 1 字节对齐（无填充字节）                     |
| 校验   | CRC8 / CRC16，覆盖 byte 0 至 N-2，最后字节存放校验值；参数见下 |

**⚠️ CRC8 有两种互不相同的实现**（对同一数据计算结果**不同**，上位机必须分别实现，不能复用同一个函数）：

- **上行帧 CRC8**（所有 15B 上行帧，云台计算、上位机校验）：**反射算法**，poly = `0x8C`（多项式 x⁸+x⁵+x⁴+1 的反转表示），init = `0xFF`，无最终异或。
- **下行 0x04 哨兵坐标帧 CRC8**（上位机计算、云台校验）：**非反射 MSB-first**，poly = `0x31`，init = `0xFF`，无最终异或。

参考实现：

```python
# 上行帧 CRC8（反射，poly 0x8C）
def crc8_uplink(data: bytes) -> int:
    crc = 0xFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc >> 1) ^ 0x8C) if (crc & 1) else (crc >> 1)
    return crc
# 校验：crc8_uplink(frame[0:14]) == frame[14]

# 下行 0x04 帧 CRC8（非反射，poly 0x31）
def crc8_coord(data: bytes) -> int:
    crc = 0xFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x31) & 0xFF if (crc & 0x80) else (crc << 1) & 0xFF
    return crc
# 打包：frame[16] = crc8_coord(frame[0:16])
```

**帧长规则**：

- 上行帧（云台 → 上位机）**统一 15 字节**，由 byte 1 的 TypeID 区分内容。
- 下行帧（上位机 → 云台）**长度不固定**，由 byte 1 的 DownlinkTypeID 决定。
- 下行 0x02 为 64 字节分片帧，两条分片需重组后才能得到完整负载。

## 二、上行帧（云台 → 上位机）

统一布局，长度固定 15 字节：

```
+--------+----------+----------------+--------+
| byte 0 | byte 1   | byte 2 .. 13   | byte 14|
+--------+----------+----------------+--------+
|  0x21  | TypeID   |  12B Data      |  CRC8  |
+--------+----------+----------------+--------+
```

CRC8 覆盖 byte 0 \~ 13。

| TypeID | 名称          | 内容                          |
| ------ | ----------- | --------------------------- |
| 0      | 常规姿态数据      | 云台 yaw/pitch + 剩余弹量 + 电容电压  |
| 1      | 比赛信息        | 比赛状态、前哨站血量、阶段剩余时间、场地事件      |
| 2      | 友方血量        | 友方 1\~4/7 号与基地血量            |
| 3      | 敌方血量        | 敌方 1\~4/7 号与基地血量            |
| 4      | Buff + RFID | 增益状态与 RFID 触发状态             |
| 5      | 友敌位置轮询      | 每帧一对友敌坐标 + 弹速               |
| 6      | 扩展数据        | UWB 偏航角、伤害差、底盘舵角与速度         |
| 7      | 哨兵信息        | 哨兵状态字 + 弹丸初速度               |
| 8      | 弹量扩展        | 弹种/射频、42mm 与堡垒弹量、金币、RFID 扩展 |
| 9      | 小地图下发指令     | 底盘收到的小地图指令回传（可选通道）          |
| 10     | 哨兵姿态时长      | 六种姿态剩余时长 + 前哨站原始血量          |
| 11     | 云台角速度/角加速度  | 云台实际 yaw/pitch 角速度与角加速度     |

## 三、下行帧（上位机 → 云台）

长度由 byte 1 的 DownlinkTypeID 决定，byte 0 恒为 `0x21`。

| TypeID | 名称      | 总长度     | 内容                       |
| ------ | ------- | ------- | ------------------------ |
| `0x00` | 常规控制帧   | 13B     | 底盘速度 + 云台角度目标 + FireCode |
| `0x01` | 哨兵命令帧   | 6B      | 哨兵命令字（复活/兑弹/姿态等）         |
| `0x02` | 小地图路径分片 | 64B × 2 | 路径数据，两片重组                |
| `0x03` | 自定义信息帧  | 36B     | 机器人间通信文本透传               |
| `0x04` | 哨兵坐标帧   | 17B     | 哨兵自身坐标                   |
| `0x05` | MPC 轨迹帧 | 26B     | 角度 + 角速度 + 角加速度前馈        |

### 3.1 DownlinkTypeID 0x00：常规控制帧（13B）

| offset | 字段         | 类型      | 含义                      |
| ------ | ---------- | ------- | ----------------------- |
| 0      | head       | uint8   | 固定 `0x21`               |
| 1      | type\_id   | uint8   | 固定 `0x00`               |
| 2      | vel\_x     | int8    | 底盘 X 速度（原始值 ÷ 50 = m/s） |
| 3      | vel\_y     | int8    | 底盘 Y 速度（原始值 ÷ 50 = m/s） |
| 4-7    | yaw        | float32 | Yaw 目标角度（deg）           |
| 8-11   | pitch      | float32 | Pitch 目标角度（deg）         |
| 12     | fire\_code | uint8   | 开火与模式位域，见下              |

> 本帧无 CRC，长度为固定 13 字节。

fire\_code 位域：

| bit | 字段         | 含义                                      |
| --- | ---------- | --------------------------------------- |
| 0-1 | FireStatus | 开火状态。**所有位反转表示开火**：`0b00` 与 `0b11` 互为切换 |
| 2-3 | CapState   | 电容状态：`00` 不用 / `01` 轻度 / `10` 重度        |
| 4   | FollowMode | 跟随模式：`1` = 底盘速度矢量跟随云台 yaw，`0` = 不跟随     |
| 5   | AimMode    | 辅瞄模式：`1` = 启用自瞄，`0` = 禁用                |
| 6-7 | Rotate     | 小陀螺档位：`0` 无速 / `1` 低速 / `2` 中速 / `3` 高速 |

行为约定：

- 上位机需以 **≥ 5Hz** 持续发送本帧，否则云台在 **200ms** 后判定上位机离线并停止执行控制命令。
- FollowMode 优先于 Rotate：FollowMode = 1 时忽略 Rotate 档位；FollowMode = 0 时才按 Rotate 档位旋转。

### 3.2 DownlinkTypeID 0x01：哨兵命令帧（6B）

| offset | 字段          | 类型     | 含义        |
| ------ | ----------- | ------ | --------- |
| 0      | head        | uint8  | 固定 `0x21` |
| 1      | type\_id    | uint8  | 固定 `0x01` |
| 2-5    | sentry\_cmd | uint32 | 哨兵命令字，见下  |

sentry\_cmd 位定义：

| bit   | 字段                                  | 含义                                                           |
| ----- | ----------------------------------- | ------------------------------------------------------------ |
| 0     | confirm\_free\_revive               | 确认免费复活                                                       |
| 1     | confirm\_immediate\_revive          | 确认兑换立即复活                                                     |
| 2-12  | exchange\_projectile\_allowance     | 非远程兑换允许发弹量累计值，必须单调递增                                         |
| 13-16 | remote\_projectile\_exchange\_count | 远程兑弹请求次数，每次只加 1                                              |
| 17-20 | remote\_hp\_exchange\_count         | 远程回血请求次数，每次只加 1                                              |
| 21-23 | posture                             | 姿态：`1` 进攻 / `2` 防御 / `3` 移动 / `4` 强化进攻 / `5` 强化防御 / `6` 强化移动 |
| 24    | confirm\_energy\_activate           | 确认能量机关进入正在激活状态                                               |
| 25-31 | —                                   | 保留，填 0                                                       |

> 本帧无 CRC。

### 3.3 DownlinkTypeID 0x02：小地图路径分片（64B × 2）

单条路径数据被拆成两个固定 64 字节的物理帧下发，上位机需先收齐两片再重组。

| offset | 字段              | 类型         | 含义                                    |
| ------ | --------------- | ---------- | ------------------------------------- |
| 0      | head            | uint8      | 固定 `0x21`                             |
| 1      | type\_id        | uint8      | 固定 `0x02`                             |
| 2      | sequence        | uint8      | 分片序号，同一路径的两片必须相同                      |
| 3      | fragment\_index | uint8      | `0` = 首段，`1` = 尾段                     |
| 4      | fragment\_count | uint8      | 固定 `2`                                |
| 5      | payload\_length | uint8      | 有效负载长度：`index 0` = 56，`index 1` = 49  |
| 6-61   | payload         | uint8\[56] | 有效负载；`index 1` 时仅前 49 字节有效，后 7 字节必须忽略 |
| 62-63  | crc16           | uint16     | 校验 byte 0 \~ 61                       |

**CRC16 参数**：反射算法，poly = `0x1021`（反转表示 `0x8408`），init = `0xFFFF`，**无最终异或**。低字节在 byte 62，高字节在 byte 63。

> ⚠️ 注意与标准 **CRC-16/X-25** 预设不同：X-25 带最终异或 `0xFFFF`，本协议没有。不要直接使用 CRC 库中的 X-25 预设，否则校验必然失败。

**重组规则**：

- 首段（index 0）负载写入缓冲区 \[0..55]，尾段（index 1）负载写入 \[56..104]，得到 105 字节完整负载。
- 两片 `sequence` 必须一致；尾段必须在对应首段之后到达。
- 首段与尾段间隔超过 **100ms** 视为超时，丢弃已收到的首段。

重组后 105 字节负载布局：

| offset  | 字段                 | 类型        | 含义                                |
| ------- | ------------------ | --------- | --------------------------------- |
| 0       | intention          | uint8     | 意图：`1` 到点攻击 / `2` 到点防守 / `3` 移动到点 |
| 1-2     | start\_position\_x | uint16    | 起点 X 坐标（dm）                       |
| 3-4     | start\_position\_y | uint16    | 起点 Y 坐标（dm）                       |
| 5-53    | delta\_x\[49]      | int8\[49] | 相对上一点的 X 增量（dm）                   |
| 54-102  | delta\_y\[49]      | int8\[49] | 相对上一点的 Y 增量（dm）                   |
| 103-104 | sender\_id         | uint16    | 发送者 ID                            |

### 3.4 DownlinkTypeID 0x03：自定义信息帧（36B）

| offset | 字段           | 类型         | 含义        |
| ------ | ------------ | ---------- | --------- |
| 0      | head         | uint8      | 固定 `0x21` |
| 1      | type\_id     | uint8      | 固定 `0x03` |
| 2-35   | custom\_data | uint8\[34] | 透传负载，见下   |

custom\_data 内部布局：

| offset | 字段                | 类型         | 含义                        |
| ------ | ----------------- | ---------- | ------------------------- |
| 0-1    | sender\_id        | uint16     | 发送者 ID                    |
| 2-3    | receiver\_id      | uint16     | 接收方选手端 ID                 |
| 4-33   | user\_data\_utf16 | uint8\[30] | 30 字节 UTF-16 原始字节（未做编码转换） |

> 本帧无 CRC。

### 3.5 DownlinkTypeID 0x04：哨兵坐标帧（17B）

| offset | 字段       | 类型         | 含义                   |
| ------ | -------- | ---------- | -------------------- |
| 0      | head     | uint8      | 固定 `0x21`            |
| 1      | type\_id | uint8      | 固定 `0x04`            |
| 2-3    | x\_cm    | int16      | 哨兵 X 坐标（cm）          |
| 4-5    | y\_cm    | int16      | 哨兵 Y 坐标（cm）          |
| 6-15   | reserved | uint8\[10] | 预留，填 `0x00`          |
| 16     | crc8     | uint8  | CRC8，**非反射变体**（poly `0x31`，与上行帧 CRC8 不同，见通用约定），覆盖 byte 0 \~ 15 |

> 建议发送频率 ≤ 10Hz（每 100ms 最多一帧）；超过 2000ms 未刷新时应停止发送。

### 3.6 DownlinkTypeID 0x05：MPC 轨迹帧（26B）

与 0x00 并行发送，只承载自瞄轨迹，不含底盘速度和 FireCode。

| offset | 字段           | 类型      | 含义                   |
| ------ | ------------ | ------- | -------------------- |
| 0      | head         | uint8   | 固定 `0x21`            |
| 1      | type\_id     | uint8   | 固定 `0x05`            |
| 2-5    | yaw          | float32 | Yaw 目标角度（deg）        |
| 6-9    | pitch        | float32 | Pitch 目标角度（deg）      |
| 10-13  | yaw\_omega   | float32 | Yaw 目标角速度（deg/s）     |
| 14-17  | pitch\_omega | float32 | Pitch 目标角速度（deg/s）   |
| 18-21  | yaw\_alpha   | float32 | Yaw 目标角加速度（deg/s²）   |
| 22-25  | pitch\_alpha | float32 | Pitch 目标角加速度（deg/s²） |

> 本帧无 CRC。
> 若本帧超过 **200ms** 未更新，云台会退回使用 0x00 帧的角度目标，并把角速度 / 角加速度前馈清零。因此停止自瞄时应停止发送本帧，而不是发送零值。
