## 二、核心数据结构

### 1. `PowerLimiter` — 功率限制器总结构体 ([PowerLimit.h:131-139](User/inc/app/PowerLimit.h#L131-L139))

```c
typedef struct {
    Torque_Scaler wheels_scaler;  // 轮电机的功率缩放器
    Torque_Scaler Steer_scaler;   // 舵电机的功率缩放器（仅舵轮底盘使用）
} PowerLimiter;
```

这是功率控制的核心，包含两组独立的 `Torque_Scaler`，分别处理轮电机(3508)和舵电机(6020)。

### 2. `Torque_Scaler` — 单组电机转矩缩放器 ([PowerLimit.h:78-129](User/inc/app/PowerLimit.h#L78-L129))

关键字段：

| 字段 | 含义 |
|------|------|
| `motor_w[4]` | 各电机当前转速 (rad/s) |
| `motor_I[4]` | 各电机当前电流（发送值） |
| `motor_w_error[4]` | 设定转速与实际转速的误差（用于转速误差分配模式） |
| `motor_R/K/B/P0` | 电机功率模型参数: `P = I²R + K·ω·I + B·ω² + P0` |
| `motor_a/b/c[i]` | 单电机的二次方程系数，用于求解缩放系数 |
| `motor_P[4]` | 各电机预测功率 |
| `send_torque_lower_scale[4]` | **核心输出**：每个电机的电流缩放系数 (0~1) |
| `predict_send_power` | 总预测发送功率 |
| `power_arrange_state[4]` | 各电机的功率分配状态 |
| `power_limit_method` | 功率限制方法：转矩削减 vs 转速误差 |

### 3. `NingCapController` — 宁王电容控制器 ([NingCap.h:79-92](User/inc/app/NingCap.h#L79-L92))

```c
typedef struct {
    float set_power;      // 底盘电机的功率期望 (核心输出)
    float cap_power;      // 电容的充电功率期望
    float cap_vol;        // 电容剩余电压 (V)
    float cap_energy;     // 电容剩余能量 (J)
    float cap_energy_percent; // 能量百分比
    BufferEnergyState buffer_energy_state; // 缓冲能量状态机
    CapVolState cap_vol_state;             // 电容电压状态机
} NingCapController;
```

### 4. `SuperPower` — 老超级电容结构体 ([SuperPower.h:52-80](User/inc/peripheral/SuperPower.h#L52-L80))

虽然大部分逻辑已废弃，但 **`power_limit_state`** 状态机仍在 `PowerStateSelect()` 中运行，控制电容/电池的物理切换：

- `POWER_LIMIT_BAT` → 电池供电
- `POWER_LIMIT_CAP` → 电容供电
- `POWER_LIMIT_BAT_ERROR` → 电容耗尽，电池勉强供电

### 5. `BufferEnergy` — 缓冲能量模型 ([SuperPower.h:87-94](User/inc/peripheral/SuperPower.h#L87-L94))

模拟裁判系统的"血量"机制，用于本地调试时估算超功率扣血。

## 三、控制逻辑脉络

### 总体流程图

```
┌─────────────────────────────────────────────────────────────────┐
│                    PowerControlTask (1kHz)                       │
│  ① 读取裁判系统 chassis_power_limit (30~200W)                     │
│  ② 根据遥控器状态/电容电压 决定策略:                                │
│     ├─ 飞坡状态 → NingCapControl(缓冲能量, max, 300W)             │
│     ├─ 电容主动模式 → max = referee + cap动态值                   │
│     ├─ 过孔标志 → max = 45W                                      │
│     └─ 普通模式 → max = referee + cap动态值                       │
│  ③ NingCapControl() 内部:                                        │
│     ├─ getCapEnergy() 计算电容剩余能量                            │
│     ├─ RefereeOutputControl() 根据缓冲能量三级状态机               │
│     │   设置 cap_power (电容充电功率)                              │
│     └─ ChassisOutputControl() 根据电容电压三级状态机               │
│         设置 cap_controller.set_power (底盘可用功率)               │
│  ④ 每4ms发送一次 CAN 0x080 → 电容板 (充电功率+缓冲能量)            │
└──────────────────────────┬──────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    ChasisControlTask (1kHz)                       │
│  ① get_sensors_info()       ← 传感器解码                         │
│  ② steer_pos_kinematics()   ← 舵轮正运动学                       │
│  ③ set_robot_speed()        ← 根据 set_power 算速度上限            │
│  ④ wheels_accel()           ← 加速度策略(TD)                     │
│  ⑤ main_control()           ← 运动学解算 → 各电机目标电流          │
│  ⑥ wheels_power_limit() ★   ← 功率限制核心 ★                     │
│  ⑦ execute_control()        ← CAN发送电流指令                     │
└──────────────────────────┬──────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│               wheels_power_limit() 详细流程                       │
│                                                                   │
│  for i=0..3:                                                      │
│    → 填入轮电机 ω, I, w_error                                     │
│    → 填入舵电机 ω, I, steer_w_error (仅舵轮)                      │
│                                                                   │
│  PowerLimit(&power_limiter, infantry.set_power)                   │
│    ├─ 舵轮底盘:                                                    │
│    │   ① 先给舵电机分配 set_power × 1.4                            │
│    │   ② 轮电机功率 = set_power - 舵电机实际消耗                    │
│    │      (保底20% ~ 100%)                                        │
│    │   ③ TorqueScaler_PowerLimit() × 2                            │
│    └─ 麦轮/全向轮:                                                │
│        直接 TorqueScaler_PowerLimit(wheels, set_power)            │
│                                                                   │
│  TorqueScaler_PowerLimit() 内部:                                  │
│    ① 计算每个电机 P = I²R + KωI + Bω² + P0                        │
│    ② 判断 predict_send_power > set_power?                        │
│       ├─ 不超: 全部 NORMAL_ARRANGE, scale=1.0                     │
│       └─ 超了:                                                     │
│          ├─ TORQUE_REDUCE_METHOD:                                 │
│          │   按各电机实际功率比例分配可用功率                        │
│          └─ SPEED_ERROR_METHOD:                                   │
│              按各电机转速误差平方比例分配可用功率                    │
│    ③ TorqueScaler_PowerScaleCal():                               │
│       对 NEED_ARRANGE 的电机解二次方程:                            │
│         a·k² + b·k + c = 0  →  k (缩放系数)                       │
│       其中 a=I²R, b=KωI, c=Bω²+P0-motor_P[i]                     │
│       特殊情况处理: c>0且b>0=无解(scale=0), 判别式<0(取顶点)       │
│                                                                   │
│  for i=0..3:                                                      │
│    wheels_set_current[i] *= wheels_scaler.send_torque_lower_scale │
│    steers_set_current[i] *= Steer_scaler.send_torque_lower_scale  │
└─────────────────────────────────────────────────────────────────┘
```

### 功率双重限制机制

代码实现了一个**双层功率保护**：

1. **上层策略 (PowerControlTask)**：根据电容电压、缓冲能量、比赛状态等，**动态决策**底盘可用功率上限 `cap_controller.set_power`
2. **下层执行 (wheels_power_limit)**：根据电机模型预测功率，按二次方程精确**削减超限电流**，使实际功率 ≤ `set_power`

## 五、两种功率限制方法对比

| | TORQUE_REDUCE_METHOD | SPEED_ERROR_METHOD |
|---|---|---|
| **分配依据** | 按各电机当前功率占比 | 按各电机转速误差²占比 |
| **策略含义** | "功率大的电机多削减" | "转速跟踪差的电机多削减" |
| **适用场景** | 轮电机（3508）— 默认 | 舵电机（6020）— 硬编码使用此方法 |

[PowerLimit.c:15-20](User/src/app/PowerLimit.c#L15-L22) 中，舵电机的 `power_limit_method` 被强制设为 `SPEED_ERROR_METHOD`。

## 六、舵轮底盘的功率分配特殊逻辑

在 [PowerLimit.c:201-215](User/src/app/PowerLimit.c#L201-L215) 中，舵轮底盘采用**功率优先分配**：

```
舵电机功率上限 = set_power × 1.4  (可超额40%)
轮电机功率 = set_power - 舵电机实际消耗
轮电机功率 = clamp(轮电机功率, set_power, set_power × 0.2)  // 保底20%
```

这种设计优先保证舵向跟踪（转向优先级高于行驶），舵电机可以暂时超功率，然后轮电机拿"剩下的"功率。

## 七、电容/电池切换状态机

在 [SuperPower.c:189-260](User/src/peripheral/SuperPower.c#L189-L260) 中（`PowerStateSelect()`）：

```
POWER_LIMIT_BAT ──(缓冲能量<5J && 电容电压>17V)──→ POWER_LIMIT_CAP
POWER_LIMIT_CAP ──(缓冲能量>55J)─────────────────→ POWER_LIMIT_BAT
POWER_LIMIT_CAP ──(电容电压<13V)──────────────────→ POWER_LIMIT_BAT_ERROR
POWER_LIMIT_BAT_ERROR ──(缓冲能量>30J)────────────→ POWER_LIMIT_BAT
```

电容切换后执行 `CAP_use()` / `Bat_use()` 的物理IO控制（`CAP_on/CAP_off/Bat_on/Bat_off` 宏）。

## 八、宁王电容的CAN通信

电容板通过 CAN 总线通信 ([PowerControlTask.c:74-79](Task/src/PowerControlTask.c#L74-L79))：

- **发送 (0x080)**: `{buffer_energy×100, P_ref×100}` — 告诉电容板当前缓冲能量和目标充电功率
- **接收**: `{cap_vol, chassis_power, referee_power, V_buckin}` — 电容板反馈电压和功率

---

**总结**：这套功率控制系统采用的是**策略层 (PowerControlTask) + 执行层 (PowerLimit)** 的双层架构。策略层负责根据比赛状态、电容电压、缓冲能量等高层信息决策"现在底盘能用多少瓦"，执行层负责用电机功率模型精确解算"每个电机的电流该打几折来精确匹配功率上限"。电容的充放电和电池切换由 `SuperPower.c` 的独立状态机管理。
