# 哨兵舵轮底盘架构图使用说明

> 本目录下的架构图由 [archify](https://github.com/tt-a1i/archify) 技能生成,描述 Sentry_Steer 底盘控制板(STM32F4 + FreeRTOS)的软件/通信架构。本文档说明如何查看、解读、修改和重新生成这张图。

---

## 1. 文件清单

| 文件 | 说明 |
|---|---|
| `sentry-steer.html` | **最终交付物**:自包含交互式架构图,浏览器直接打开即可,无需服务器 |
| `sentry-steer.architecture.json` | 图的**源文件**(声明式 JSON),修改后可重新渲染更新 HTML |
| `项目架构文档_Chassis.md` | 架构信息来源(图的节点/连线均取自该文档) |
| `架构图使用说明.md` | 本文档 |

## 2. 如何查看

用任意现代浏览器(Edge / Chrome / Firefox)直接打开 `sentry-steer.html`,支持:

- **视图切换**:顶部提供 3 个预设视角
  1. *1 kHz 主控链路* — 云台指令 → CAN2 → 主控 → 运动学 → CAN1 → 电机
  2. *功率与超级电容* — 裁判系统 → 功率控制 → 电容板
  3. *数据回传与裁判上报* — 正运动学反解 / 裁判数据回传云台
- **缩放 / 平移**:鼠标滚轮缩放,拖拽平移
- **图例**:左下角区分节点类型(后端 / 云服务 / 消息总线 / 外部系统)
- **结论卡**:3 张要点卡(cyan/rose/emerald)概括各链路设计

## 3. 图内容速读

### 3.1 节点(11 个)

| 节点 | 类型 | 位置含义 |
|---|---|---|
| 云台板 / 上位机 | 外部系统 | 控制指令来源 |
| CAN2 板间总线 | 消息总线 | 云台联指挥链路 |
| 底盘主控任务 | 后端 | ChasisControlTask · 1 kHz |
| 舵轮运动学 | 后端 | steer.c 逆/正解 + 舵向最优旋转 |
| CAN1 电机总线 | 消息总线 | 4×M3508 轮毂 + 4×GM6020 舵向 |
| 底盘电机执行 | 外部系统 | 电机硬件 |
| 云台通信任务 | 后端 | GimbalTask · 5 ms |
| 裁判系统 | 外部系统 | UART4 串口 |
| 裁判通信任务 | 后端 | RefereeTask · 10 ms |
| 功率控制任务 | 云服务样式 | PowerControlTask · 1 kHz |
| 超级电容板 | 外部系统 | 宁王电容 |

节点分两组:上排为**主控执行链**,下排为**支撑链**(裁判/功率/回传);7 个板内节点被区域边界"底盘控制板 · STM32F4 · FreeRTOS"包裹。

### 3.2 关键连线(12 条)

- `0x150 / 0x151 / 0x15A`:云台 → CAN2 下发指令(高亮)
- `指令解码 → 设定速度/角速度`:CAN2 → 主控任务(高亮)
- `target → 逆运动学`:主控 → 舵轮运动学(高亮)
- `0x201~0x208`:CAN1 → 电机电流帧
- `功率上限 · 缓冲能量`:裁判任务 → 功率控制(高亮)
- `CAN2 双向 · 0x050 / 0x051`:功率控制 ↔ 电容板
- 虚线:`正运动学反解`、`裁判映射 · 0x0303 小地图`(回传类)

## 4. 如何修改

### 4.1 修改工作流(3 步)

```bash
# ① 编辑源文件后,先校验(showcase 为最高质量档)
node "%USERPROFILE%\.agents\skills\archify\bin\archify.mjs" validate architecture sentry-steer.architecture.json --quality showcase

# ② 校验通过后重新渲染
node "%USERPROFILE%\.agents\skills\archify\bin\archify.mjs" render architecture sentry-steer.architecture.json sentry-steer.html --quality showcase

# ③ 对输出 HTML 做最终检查
node "%USERPROFILE%\.agents\skills\archify\bin\archify.mjs" check sentry-steer.html
```

> Git Bash / WSL 用户把 `%USERPROFILE%` 换成 `$USERPROFILE`,路径分隔符用 `/`。

### 4.2 JSON 结构说明

```jsonc
{
  "components": [          // 节点
    {
      "id": "chassis_ctrl",           // 唯一 ID
      "type": "backend",              // backend | cloud | messagebus | external ...
      "label": "底盘主控任务",         // 主标题(短,避免重叠)
      "sublabel": "ChasisControlTask · 1 kHz",  // 副标题
      "pos": [420, 180]               // ⚠ 左上角坐标(非中心),默认节点 120×60
    }
  ],
  "boundaries": [          // 区域边界
    { "kind": "region", "label": "底盘控制板 · STM32F4 · FreeRTOS",
      "wraps": ["can2", "chassis_ctrl", "..."], "pad": 16 }
  ],
  "connections": [         // 连线
    {
      "from": "gimbal", "to": "can2",
      "label": "0x150 / 0x151 / 0x15A",
      "variant": "emphasis",          // emphasis 高亮 | dashed 虚线 | 默认实线
      "labelAt": [150, 150]           // 可选:强制标签位置(左上角坐标)
    }
  ],
  "views": [...],          // 顶部视图切换(focus 节点 id 数组 + note)
  "cards": [...]           // 结论卡(dot: cyan|rose|emerald, title, items[])
}
```

### 4.3 常见校验错误与修复方法

| 错误 | 原因 | 修复 |
|---|---|---|
| `Label ... overlaps component` | 标签压到节点上 | 加 `labelAt`(标签左上角坐标)移到空白处,或缩短标签 |
| `less than 8px apart` | 两节点太近 | 调整 `pos`,保证节点间距 ≥ 8px(建议 ≥ 20px) |
| `crosses component (unrelated)` | 连线穿过无关节点 | 挪节点位置让出走廊,或用 `via` 指定折线路径 |
| `endpoint-side-direction` | 自定义 route 方向与推断端口侧矛盾 | 去掉手写 route 让渲染器自动布线 |
| `proper-crossing` | 无关连线互相交叉 | 用 `via` 分离走廊(错开 Y 值 ≥ 4px) |
| `label-route-clearance` | 标签离其它连线 < 4px | `labelAt` 移远,或改另一条线的 `via` |
| desktop-readability | 整图过宽导致缩放后文字过小 | 控制横向跨度 ≤ ~1000px(压缩列数或改纵向布局) |

**布局经验**(本项目实测):

- 主链路 6 节点横向超过 1023px 会被判"桌面不可读",改为**主轨横排 + 辅助任务下沉**布局
- 一条连线短于 60px 时标签放不下,放 `labelAt` 到轨道**上方/下方**空白带
- 汇聚到同一节点多条边时,错开来源方位(左/右/下),避免端口争抢产生折线穿节点

### 4.4 修改后必查清单

- [ ] `validate` 输出 `"ok": true` 且 composition `errors: 0, warnings: 0`
- [ ] `render` 重新生成 HTML
- [ ] `check` 输出 `"ok": true`
- [ ] 浏览器打开确认:视图切换正常、无文字重叠、连线清晰

## 6. 与代码同步维护

架构图是**手动维护**的,代码变更时请同步检查以下映射是否仍然成立:

| 图中元素 | 对应代码 |
|---|---|
| ChasisControlTask 1 kHz | `Chassis/Task/src/ChasisControlTask.c`(注意目录内拼写为 Chasis) |
| GimbalTask 5 ms | `Chassis/Task/src/GimbalTask.c` |
| RefereeTask 10 ms | `Chassis/Task/src/RefereeTask.c` |
| PowerControlTask 1 kHz | `Chassis/Task/src/PowerControlTask.c` |
| steer.c 逆/正解 | `Chassis/User/src/app/steer.c`(头文件 `User/inc/app/steer.h`) |
| CAN ID 0x150/0x151/0x15A、0x160、0x050/0x051、0x201~0x208 | `Chassis/Mylib/src/can1.c`、`can2.c`、`can_send.c`、`can_receive.c` |
| 0x0303 小地图 | `RefereeTask.c` 裁判协议映射部分 |

若发现图与代码不一致:先改 `sentry-steer.architecture.json`,再走 §4.1 三步流程更新 HTML,最后提交两个文件到 Git。
